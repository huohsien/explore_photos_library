6. 重新理解問題層級

真正應該優先處理的是：

A. FOLDER_MISSING_FROM_CURRENT: 5
B. ALBUM_MISSING_FROM_CURRENT: 48
C. ALBUM_FOLDER_PATHS_CHANGED: 318
D. 最後才是 ASSET_ALBUM_MEMBERSHIP_CHANGED / ASSET_FOLDER_PATHS_CHANGED

因為 asset-level 的 12,630 / 19,286 很可能是上層 folder / album 結構壞掉造成的連鎖結果。

例如：

* 一個 missing album 有 5,000 張照片，就會造成 5,000 筆 asset album membership changed。
* 一個 folder 裡有 10 個 albums，每個 album 有 1,000 張，若 folder path 壞掉，就可能造成 10,000 筆 asset folder path changed。

所以不能從 12,630 張一張一張手工修，要從 album/folder 層級修。

7. PowerPhotos copy whole album 的問題

如果用 PowerPhotos 從 Backup copy 整個 missing album 到 Current：

* 可能會建立正確 album
* 但 Current 裡本來已經存在的照片可能又被 import 一份
* 造成 duplicate
* 新 import 的照片 Date Added 會變成今天
* Recently Added 會被污染
* 後面還要刪 duplicate，非常麻煩且危險

所以 PowerPhotos copy album 不能作為大規模修復策略，只能作為小量或最後 fallback。

8. 正確方向：Python manifest + Swift PhotoKit repair tool

現在比較合理的架構是：

Python / osxphotos:

* 繼續做 forensic comparison
* 找出 missing albums、broken album paths、asset membership loss
* 產生 TSV / JSON repair manifest

Swift / PhotoKit tool:

* 讀 manifest
* 在 Current Photos Library 建立 folder / album
* 找到 Current 裡已存在的 assets
* 把既有 assets 加進指定 album
* 不重新 import
* 不製造 duplicate
* 不污染 Recently Added

這才是自動化的核心。
